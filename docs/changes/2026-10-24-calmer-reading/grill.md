# Calmer reading decisions

The user asked whether Markside's reading experience is clean and minimal
compared with Typora. The agent proposed five changes; the user answered each in
chat.

## Q1. How should inline code look?

The agent proposed replacing red inline code with a neutral color. The user
agreed, provided readers can still tell that the text is code with a special
meaning. Agreed: foreground-colored monospace text on a subtle muted background
with small padding and rounded corners.

## Q2. Should headings keep their rules?

The agent proposed dropping or lightening the rules under H1 and H2. The user
asked that H2 stay distinguishable from H3, and noted that many people use
Markside as a preview before pushing to GitHub. Agreed: keep the GitHub rules
under H1 and H2 at reduced contrast. H2 stays larger than H3 and keeps its rule.

## Q3. What should the page widths be?

The agent proposed a default width of about 70–75 characters. The user asked
whether the narrow width should become the default with a wider option, then
chose **Standard / Extended / Full width**. Agreed: Standard is 48rem and the
default, Extended is 64rem, and Full width has no maximum. Existing explicit
choices keep their widths.

## Q4. How should the word count appear?

The user chose to keep it visible, more quietly.

## Q5. Should the file tree start open?

The user agreed that the file tree starts collapsed, provided users still know
that a file tree exists. Explicit open or closed choices are kept.

## Q6. Which release?

The user chose 1.7.0.
