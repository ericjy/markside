# Issues and technical design notes

Use [GitHub issues](https://github.com/ericjy/markside/issues) for public bug
reports and feature proposals. Include reproduction steps, expected behavior,
and a safe sample where useful. Follow `CONTRIBUTING.md` before starting a
substantial change.

Technical specs may accompany a branch under `.scratch/<feature-slug>/spec.md`.
Existing specs provide historical context; current behavior belongs in
`docs/system-design.md` and durable architectural decisions belong in `docs/adr/`.

Do not commit private research, business plans, customer information, credentials,
or personal notes. Keep those outside the repository. The `.scratch/` directory
is not ignored as a whole because some technical specs are shared project docs.
